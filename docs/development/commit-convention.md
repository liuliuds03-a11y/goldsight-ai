# GoldSight AI V3.0 - 提交规范

## 概述

规范的提交信息是项目可维护性的基础。所有提交必须遵循以下格式。

## 提交信息格式

```
<type>: <description>
```

- **type**（必填）：提交类型，使用下表中的标识符
- **description**（必填）：简明扼要的变更描述，使用中文，不超过 72 个字符

## 提交类型

| Type | 说明 | 示例 |
|------|------|------|
| `feat` | 新功能 | `feat: 添加黄金价格实时监控模块` |
| `fix` | 修复缺陷 | `fix: 修复汇率转换精度丢失问题` |
| `docs` | 文档变更 | `docs: 更新 API 接口文档` |
| `style` | 代码格式（不影响逻辑） | `style: 统一后端代码缩进为 4 空格` |
| `refactor` | 代码重构（非新功能、非修复） | `refactor: 重构数据采集管道模块` |
| `test` | 添加或修改测试 | `test: 添加用户认证单元测试` |
| `chore` | 构建/工具/辅助工具变更 | `chore: 更新 Docker 基础镜像版本` |

## 扩展格式（可选）

对于复杂变更，可使用多行格式：

```
<type>: <简短描述>

<详细说明（可选，解释变更的原因和影响）>

<关联信息（可选，Issue 编号等）>
```

### 示例

```
feat: 添加多金属价格预警推送功能

实现基于 WebSocket 的实时价格预警系统，支持用户自定义
价格阈值和推送频率。

Closes #42
```

## 规则

1. **使用中文**描述变更内容
2. **description 首字母不大写**，末尾不加句号
3. **一个提交做一件事**，避免混合不相关的变更
4. **type 使用小写英文**
5. **禁止无意义的提交信息**，如 `update`、`fix bug`、`修改`

## Agent 提交指引

| Agent | 常用 Type | 说明 |
|-------|----------|------|
| 后端 Agent | `feat`、`fix`、`refactor` | 后端功能与修复 |
| 前端 Agent | `feat`、`fix`、`style` | 前端功能与样式调整 |
| 数据库 Agent | `feat`、`refactor`、`chore` | 数据库变更与迁移 |
| 部署 Agent | `chore`、`fix` | 配置与部署修复 |
| 版本管理 Agent | `docs`、`chore` | 文档与流程管理 |

## 自动校验

项目提供提交格式检查 Skill，可在提交前自动校验格式合规性。
详见项目 Skills 目录。
